## 1. Capture target definition

### 1.1 What "raw content" is

A payload of unstructured user-visible text or
binary that was supplied by the customer, the
customer's user, or generated by a model on their
behalf. Specifically:

| Item captured                                              | Considered raw | Considered metadata |
| ----------------------------------------------------------- | -------------- | ------------------- |
| LLM prompt (request body, user / system messages)           | YES            | —                   |
| LLM completion (response body)                              | YES            | —                   |
| Tool call arguments / outputs                               | YES            | —                   |
| Multimodal attachments (image/audio/document bytes)         | YES            | —                   |
| Plugin payload (eval input + scores)                        | YES (input)    | scores (metadata)   |
| Eval profile `prompt_template`                              | YES            | —                   |
| Benchmark fixture file                                      | YES            | —                   |
| Truncated previews (> 200 chars)                            | —              | partial (treated as YES) |
| Token counts, model latency, aptrace IDs                    | —              | metadata            |
| apierr.Code, audit detail row                               | —              | metadata            |
| Hash of payload (sha256, sha256:8)                          | —              | metadata            |

### 1.2 Boundary: when does a row stop being a capture?

A row becomes `capture=false` when only metadata
fields are persisted (`body_plain IS NULL` in
ClickHouse, no `payload` column in audit/eval
profile, no `value` blob in Redis cache beyond
TTL-capped hash+insight). Once `capture=true`,
those columns become populated exactly per the
toggle. A row that has `capture=true` in DB but
`capture.enabled=false` at the org policy layer
is a bug and a D-2c.7 leak-prevention test
fails on it.

### 1.3 Hook points where a writer must consult the policy

| Layer | File / path                          | Decision point |
| ----- | ------------------------------------ | -------------- |
| Gateway request finalize              | `internal/gateway/handler.go` (PostHook) | bind `raw_cap=policy.capture.requestResponse.enabled` |
| Eval profile save                     | `internal/evalprofile/store.go` (`Save`) | `policy.evalProfile.attachTemplate` |
| Plugin OTLP emit                      | `internal/evalplugin/emit.go`           | per-vendor `policy.pluginOutbound.<vendor>.enabled` |
| Redis cache write                     | `internal/cache/cache.go` (`Set`)        | already hashed; payload-row is TTL-only |
| Backup runner                         | `cmd/nexus-backup` (`Bundle`)            | `policy.backup.enabled` |
| Support bundle runner                 | `cmd/nexus-support-bundle` (`Collect`)   | `policy.supportBundle.enabled` |
| DB `chat_request_response` write      | `internal/chat/store.go`  (`Insert`)     | `policy.capture.requestResponse.enabled` |

The decision wrapper is a single function
`capture.Decide(orgID, layer)` that reads the
org policy from a cached value, returns whether
the layer writes raw content and where. Logging
and metrics decorate it.

## 2. Capture surface inventory

(`docs/d2c-design-inventory.md` is the source of
truth; this section pins the names.)

| Surface                                   | Storage                   | Default      | Toggle                                        |
| ----------------------------------------- | ------------------------- | ------------ | --------------------------------------------- |
| Chat request/response raw                 | Postgres `chat_request_response.body` | OFF | `capture.requestResponse.enabled` |
| Chat request/response hash-only fallback  | Postgres `body_sha256`    | ON (always)  | n/a — always written as metadata              |
| ClickHouse trace event body_plain         | ClickHouse `chattrace_event.body_plain` | OFF    | `capture.traceRaw.enabled` |
| ClickHouse trace event hash column        | ClickHouse `body_sha256`  | ON (always, hash) | n/a                                      |
| Object storage raw                        | S3/GCS `chattrace-downloads/{org}/{request}.json` | OFF | `capture.persistToS3.enabled` |
| Redis cache (prompt id key + payload val) | `internal/cache` in-memory + Redis | ON (TTL≤7d) | TTL controlled; payload never raw if `capture.enabled=false` |
| Eval profile template                     | `eval_profile.prompt_template` | OFF        | `capture.evalProfile.attachTemplate` |
| Plugin payload (OTLP body)                | vendor receptacle        | OFF          | `capture.pluginOutbound.<vendor>.enabled`     |
| Benchmark fixture file                    | benchmark volume          | OFF          | `capture.benchmark.enabled`                   |
| CSV export                                | admin download            | OFF          | `capture.exportEnabled` per export-type       |
| Backup bundle (`tar.gz`)                  | operator bucket           | OFF          | `capture.backup.enabled`                      |
| Support bundle                            | operator bucket           | OFF          | `capture.supportBundle.enabled`               |

This table is exported as JSON to
`internal/capture/inventory.json` at build
time; tests asserting that no other column
contains raw content run against this
inventory. A column that appears in a SQL
migration but not in the inventory will
fail D-2c.7.

## 3. OFF default + opt-in

### 3.1 Cluster boot

- Helm `values.yaml` defaults all
  `capture.*` flags to `false`.
- `cmd/nexus/main.go` boot policy:
  on read of `capture.enabled` (or any
  subflag) returns `false` if the value is
  not set in env.

### 3.2 Per-org policy

- New table: `org_capture_policy`
  (migration `026_org_capture_policy.sql`).
  Columns: org_id (PK), capture_policy JSONB,
  updated_at, updated_by_user_id, audit_id (FK).
- Read path: cached at gateway boot,
  invalidated on UPDATE.
- Write path: org admin through the console's
  Capture settings page. Each write is
  recorded in `audit_logs` with action
  `capture.policy.update` and old/new JSON.

### 3.3 Audit on activity

Every toggle change emits an audit record:

```
audit_log row {
   action: "capture.policy.update"
   org_id: ...
   user_id (operator|org_admin): ...
   old_policy: <json>
   new_policy: <json>
   feature_flag_window: ...
}
```

The audit row is append-only and enforced via
the same migration as the existing audit log.

### 3.4 Console

- Console route `/admin/capture-policy` is
  gated behind `org_admin` role.
- Static empty-state UI shows
  "Capture is OFF for this org".
- Activation UI red-banners:
  - retention period choice
  - redaction level (default hash-only)
  - legal hold disclosure
- Mutation must require explicit "I
  understand this stores raw content
  boundary-crossing" confirmation.

## 4. Retention / delete / redaction / legal hold

### 4.1 Retention floors

- Cluster-level minimum: 0d (immediate purge).
- Allowed values: 0d, 1d, 7d, 30d, 90d,
  1y (legal hold), `permanent`.
- An org setting 7d when the cluster
  floor is 30d is rejected at the
  capture-policy API with a 400.

### 4.2 Deletion

- A daily cron sweeps each capture surface
  table: rows older than their
  `org_capture_policy.retention_days`,
  which lacks a `legal_hold=true` flag.
- Org admins trigger immediate purge via
  `nexus-capture-cli delete --org <id>
  --before <rfc3339>` (also generates
  audit entry).
- A "show me what gets purged" preview
  is available before commit.

### 4.3 Encryption at rest

- Postgres: AES-GCM via pgcrypto with
  envelope encryption.
- S3: SSE-KMS, key per org. Cluster
  default key when org does not BYOK
  yet.
- ClickHouse: AES-GCM envelope, key
  per org.
- ClickHouse `body_sha256` is *not*
  encrypted (it's a hash, not PII by
  itself).

### 4.4 Key rotation

- Operator-initiated cron rotates the
  per-org ocean-key and re-encrypts
  columns.
- Rotation period ≤90 days by default.
- Old keys stay available for ≤24h
  for in-flight reads.

### 4.5 Redaction

- "Hash-only" is the default when
  capture is on but redaction level is
  unset.
- "Preview" mode allows: 200-char
  truncated plain + body_sha256 +
  flags.
- "Full" mode means plaintext. Used
  only when explicitly chosen.
- Boundary: human-readable `eval_score`
  output is *metadata*; the actual
  plain-text input cell in csv export
  carries the same redaction level as
  the capture policy.

### 4.6 Legal hold

- Operator-only action puts `legal_hold=true`
  on an org's policy.
- Capture cron skips rows that have
  `legal_hold=true` for that org, even
  after retention expires.
- A separate audit action
  `capture.legal_hold.<set|release>` is
  recorded.

## 5. External evaluators / plugins combined with egress proxy

### 5.1 The combined rule

```
capture.pluginOutbound.<vendor>.enabled
   AND
networkPolicy.egress.<vendor>.hostSet
```

Only when both are true does the chart
admit a NetworkPolicy egress rule that
allows the gateway to talk to that
vendor. That means a vendor with capture
on but no egress rule admits its
address is reachable; a vendor with
egress rule admits but capture off has
no plaintext to send. Either side off is
the default.

### 5.2 Vendor URL whitelisting

- Allowed URL set is **only** the URL
  declared in `networkPolicy.egress.proxy.host`
  or per-vendor URL sub-fields. The
  runtime does *not* resolve DNS names
  other than those.
- Vendor URLs that resolve to IPs not in
  the chart's allow-list are dropped at
  the socket layer.

### 5.3 Credential hygiene

- Vendor credentials live in operator
  Secrets (existing pattern).
- Logs / metrics / errors / traces must
  redact credential strings
  (e.g. `api_key=***`). D-2d verifies
  this via grep-equality tests.

## 6. Capture-aware NetworkPolicy gating

### 6.1 Chart addition

```yaml
networkPolicy:
  egress:
    clickhouse:
      enabled: false          # default
      namespace: ...
      selector: {role: clickhouse}
      ports: [9000, 8123]
    objectStorage:
      enabled: false          # default
      bucket: ...
      ipBlockMode: cidr
      ipBlockCidrs: [...]
```

### 6.2 When capture is OFF (default)

- chart does NOT render the
  `egress-clickhouse` block.
- chart does NOT render the
  `egress-objectStorage` block.
- The default-deny NetworkPolicy keeps
  gateway / worker / migration from
  shipping any outbound plaintext.

### 6.3 When capture is ON

Operator sets
`networkPolicy.egress.clickhouse.enabled=true`
and (independently)
`capture.requestResponse.enabled=true` in
the org policy. The chart renders the
egress rule but the runtime client
keeps the toggle and writes only when
the org policy permits. Mismatch is a
log error, not a crash.

### 6.4 D-2b inventory test addition

Add to
`internal/contracttest/d2b_fixture_label_conformance_test.go`
(or sibling) a check:

```
TestCaptureNetworkPolicyAdheres /
   feature (capture.enabled=false):
     - rendered NetworkPolicy must NOT contain
       egress.clickhouse rule
     - rendered NetworkPolicy must NOT contain
       egress.objectStorage rule
   feature (capture.enabled=true):
     - rendered NetworkPolicy MUST contain
       egress.clickhouse rule
     - rendered NetworkPolicy MUST contain
       egress.objectStorage rule
```

This is static: it inspects the rendered
manifest in two values configurations,
compares to expected union of egress
blocks, and fails if a rule appears in
the wrong setting.

## 7. Negative tests: leak prevention

### 7.1 Before-fix tests

For each capture surface, write a unit
test that asserts (currently) the
runtime writes the raw content
**even if capture is OFF**. These
tests are intentionally failing before
D-2c ships. They are the "before-fix
failure reproduction" the user
mandated.

| Surface                                  | Failure repro test                           |
| ---------------------------------------- | -------------------------------------------- |
| Postgres `chat_request_response.body`    | `TestCaptureRequestResponse_LeakBefore`      |
| ClickHouse `chattrace_event.body_plain`  | `TestCaptureTrace_LeakBefore`                |
| S3 `chattrace-downloads/...json`         | `TestCaptureObjectStorage_LeakBefore`        |
| Redis cache value beyond TTL             | `TestCaptureRedis_LeakBefore`                |
| Eval profile `prompt_template`           | `TestCaptureEvalProfile_LeakBefore`          |
| Plugin OTLP body                         | `TestCapturePluginOTLP_LeakBefore`           |
| Benchmark fixture attachment             | `TestCaptureBenchmark_LeakBefore`            |
| CSV export cell                          | `TestCaptureCsvExport_LeakBefore`            |
| Backup bundle payload                    | `TestCaptureBackup_LeakBefore`               |
| Support bundle                           | `TestCaptureSupportBundle_LeakBefore`        |

### 7.2 After-fix tests

After D-2c.1 … D-2c.6 land, the same tests
flip their expected outcomes (capture
remains OFF by default; the test now
asserts the body_plain cell is empty /
the file is not created / etc.). The
logic of "this row is the audit trail
proving we used to leak" remains
intact in git history.

### 7.3 CI gate

The tests run under
`-tags=capture_negative` on every PR.
A PR that claims "leak fixed" must pass
the after-state tests. A PR that
modifies a capture-related hook without
matching tests must add them in the
same PR or be rejected by reviewer
policy.

## Open questions for the user

1. **CSV export redaction default**.
   Should csv export with capture on
   default to "preview" redaction (200
   chars) or to "hash"? The user must
   answer.
2. **Legal hold granularity**. Per-org
   is straightforward. Per-request is
   possible but requires a new
   column on every capture row. For D-2c
   we propose per-org; per-request is
   deferred.
3. **Daily cron timezone**. Capture
   sweep runs once per day. When? UTC
   midnight is clean; midnight in the
   org's home TZ is more friendly. For
   D-2c we propose UTC midnight and
   add a follow-up note for opting-in
   to org TZ.
